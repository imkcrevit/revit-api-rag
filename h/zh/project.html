V 数据管线
VI 工具固化

原理

当生成的代码成功执行后，它会结晶为可复用的 YAML 工具，并带有参数化占位符。下次调用完全跳过 RAG 和 LLM。

参数化

LLM 将硬编码值替换为 {占位符} — 墙类型变为 {type_name}，标高变为 {level_name}，尺寸变为 {width}。每个占位符标注类型和可选的 choices_from。

动态选项

带有 choices_from 的参数会查询实时 Revit 模型。"levels" 获取实际标高名称，"family_types:OST_Walls" 获取当前项目中的墙类型。用户从列表中选择 — 无需手动输入。

存储

工具以人类可读的 YAML 格式存储在 /mcp_bridge/tools/ 中。可版本控制、可导出、可组合。包含元数据：创建日期、源查询、执行次数。

YAML Tool Example 
name: create_structural_column
display_name: Create Structural Column
description: Place a structural column at specified coordinates

parameters:
  - name: type_name
    type: string
    choices_from: family_types:OST_StructuralColumns
  - name: level_name
    type: string
    choices_from: levels
  - name: x
    type: double
    description: X coordinate (mm)

code_template: |
  // Queries Revit for live data — no hardcoded values
  var symbol = collector
    .FirstOrDefault(s => s.Name == "{type_name}");
  ...
VII 运行逻辑

首次查询

完整管线：改写 → 嵌入 → 搜索 → 重排序 → 生成 → 沙箱 → 执行。LLM 密集型，总计约 15-30 秒。代码基于 RAG 上下文从零生成。

重复查询

匹配到已固化工具后加载 YAML 模板，从用户输入或 Revit 实时数据填充参数，直接执行。零 LLM 成本，亚秒级响应。

编译失败

Roslyn 错误连同原始上下文反馈给 Claude。自动重试生成修正代码 — 最多 2 次尝试。大多数错误在首次重试时解决。

API 浏览器

独立搜索模式 — 交互式浏览 27,596 条 API 条目。结果以排序表格展示，含语法、参数和备注。点击任意 API 即可生成可运行的代码示例。

意图桥接

专用的槽位填充中间件。LLM 分类交互类型 — 直接查询、族选择、元素拾取或复合 — 并路由到相应的参数流程。
